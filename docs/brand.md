# Кастомная вёрстка: папка `brand/`

Результат спайка. Контракт, на который опираются этапы 2a (поддержка в шаблоне) и 3 (агент).

## Контракт

| Файл                                         | Роль                                                                                                                                                                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `brand/Header.vue`, `Footer.vue`, `Hero.vue` | подменяют стандартные части; нет файла — стандартная часть                                                                                                                                                                   |
| `brand/styles.css`                           | подключается в сборку, если файл есть                                                                                                                                                                                        |
| `brand/blocks/<Key>.vue`                     | свой блок вместо общего; `<Key>` — имя из карты шорткодов `RuntimeTemplateLayout` (`DataTable`, `Faq`, `TableContent`, `ButtonRef`, …). Пропсы те же, что у стандартного блока. Фиксы общего блока до такой копии не доходят |
| `brand/theme.json`                           | тема целиком вместо `settings.uiTheme`; недонастроенная (нет `mode` или любого из 9 цветов) игнорируется. Шрифт из её `type` сервер встраивает так же, как шрифт темы из базы (`#brand-theme` в `nuxt.config.ts`)            |
| `brand/site.json`                            | форма `SiteConfig` (меню, CTA, футер, тексты) поверх `seo.conf.ts` и `settings`; пустые значения не перекрывают. Меню, ссылки и текст подвала, сохранённые в панели (`settings.navigation`), главнее этого файла             |

**Навигация из панели.** Поле `settings.navigation` (`headerLinks`, `footerLinks`, `footerTitle`, `footerBody`) пишет только форма «Шапка и подвал» и накладывается на конфиг последним, поверх `brand/site.json` (`applyNavigation` в `shared/utils/site-config.ts`); пересборка образа не нужна. Пункты шапки `kind: "page"` заменяются целиком и встают на место первого убранного с его `position` и `style`; нет такого пункта — сразу после логотипа, `left`/`link`. Логотип и кнопки `ref` остаются из вёрстки. Выпадашка `children` у заменяемого пункта теряется — в панельной навигации выпадашек нет. Подвал заменяется по полям. Запись с `explicit: true` (так пишет форма с v1.22.0) главнее вёрстки целиком: пустой список или строка — осознанное «нет», и удалённое не возвращается из `brand/site.json`. Запись без `explicit` старая: пустое поле в ней не перекрывает вёрстку, потому что «удалили» не отличить от «не трогали». Приоритет `settings.layout` над `site.json` не менялся: применение манифеста переписывает `layout.*` дефолтами и затёрло бы вёрстку.

**Рефки по кнопкам.** Поле `settings.refs` (`defaultSlug`, `blocks`, `buttons`; значения — slug казино) пишет только панель, вкладка «Казино» окна сайта; пересборка образа не нужна. Решатель один — `useRefLink(ключ, блок)` (ref с адресом) и `useRefLinks()` (функция `(ключ, блок, запасной адрес?) => адрес` для кнопок в цикле). Порядок: выбор кнопки → выбор её блока → казино по умолчанию → `brandSlug` → `/`. Чистая часть — `shared/utils/ref-link.ts`; slug, которого нет среди казино сайта, репозиторий настроек отдаёт как невыбранный. Явная `link` пункта меню — последний запасной вариант после выбора панели. Свой `slug` реф-кнопки статьи главнее выбора панели (пустой идёт в блок `article`); кнопки внутри `data-table` (проп `tableCell`) выбора панели не знают вовсе.

Ключи стандартных кнопок — `shared/constants/ref-buttons.ts` (`hero.cta`, `sticky.cta`; пункты меню `kind: "ref"` — `header.ref.<refLabelSlug(подпись)>`). В `brand/` реф-кнопка зовёт тот же `useRefLink` / `useRefLinks`, а блоки и кнопки вёрстки перечислены в **`brand/refs.json`**: `[{ "block": "lobby", "label": "Лобби", "buttons": [{ "key": "lobby.gates-of-olympus", "label": "Gates of Olympus" }] }]`. Панель читает файл из репозитория; ключ, которого нет в файле, она не покажет. Хардкод `/go/<slug>/` в `brand/` запрещён.

Перекраска общих блоков без копии — стилями в `brand/styles.css` по `[data-part="table|faq|toc|button"]`.

Обёртки статьи — `<aside class="brand-tip|brand-warning|brand-card|brand-quote">` и `<aside class="brand-cols">` с двумя `<aside class="brand-col">` внутри — приходят в тексте статьи из панели (импорт из Markdown, набор `ARTICLE_WRAPPERS` в appspro). Своих стилей у шаблона для них нет: оформляет их `brand/styles.css`, без него это обычные блоки.

**Баннер страницы.** Данные — `banner` страницы (`ribbon`, `text` — бонус, `buttonText`, `img`), правятся в панели; `brand/Hero.vue` читает их через `usePageHero()` → `{ ribbon, bonus, img, buttonLabel, buttonLink, hasCta, hasHero }`. Нет картинки и бонуса — `hasHero` ложь, и рисовать нечего. Страница без своей картинки берёт общий баннер сайта (`settings.brand.banner`, `resolveHeroImage`); alt страницы, если вписан, важнее общего, а правка картинки на одной странице на другие не переходит. Без `brand/Hero.vue` шаблон сам рисует `PostHeroLayout` (текст слева, картинка справа), но только когда у баннера есть картинка: старые страницы без неё выглядят как раньше. Ссылка кнопки — та же, что у шапки и липкой панели (`usePageOffer`).

Картинка баннера — приоритетная картинка страницы: `usePriorityImage()` отдаёт `place: "hero"`, и тогда картинка лида приоритета не получает. Hero-картинка выбирается только через `usePriorityImage` / `useResponsiveImage`: на странице не больше одной приоритетной картинки (`perf-smoke --expect-priority`).

schema.org строит `usePostSchema()`; в `brand/` его не вызывают и не подменяют.

Обновление шаблона `brand/` не трогает. Статьи, SEO, schema.org, хлебные крошки, правила картинок, `/go/` и кеш из `brand/` не переопределяются.

## Подтверждено спайком

| Пункт                | Итог                                                                                                                                                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Опциональный glob    | `import.meta.glob("~~/brand/*.vue", { eager: true })` в `app/utils/brand.ts`. Без папки — пустой объект, сборка зелёная. Голый `/brand/…` у Nuxt ничего не находит — только алиас `~~`. Ключи приходят как `../brand/X.vue`, поэтому поиск по суффиксу |
| Своя шапка в бандле  | фикстура попадает в серверный бандл `layouts/default`. SSR на живой странице не проверен: в базе из `.env` нет постов                                                                                                                                  |
| Tailwind и стили     | `./brand/**/*.vue` в `content`; `css: [brand/styles.css]` в `nuxt.config.ts` только при наличии файла, в серверные стили попадает                                                                                                                      |
| Фикстура             | `tests/fixtures/brand-sample/`; сборка с ней — `cp -r tests/fixtures/brand-sample brand && npm run build`                                                                                                                                              |
| Draft-тег на staging | `buildStagingImage` в `appspro/shared/utils/staging-slots.js` зашивает `:latest`. Правка: необязательный параметр тега, один вызов в `staging-jobs.js` и тест. `main-server` не меняется — образ слота задаётся переменной `SITEn_IMAGE`               |

## Не проверено

- Побайтное совпадение SSR у сайта без `brand/` — нужна страница с контентом (этап 2a).
- Гидрация кастомной шапки в браузере.
- Совместимость `brand/styles.css` с `theme-css-layers.test.ts`.

## Сборка черновика

appspro собирает ветку `layout-draft` через `app_build_push.yml` с input `image_tag: draft`: образ уходит под `:draft` и `:<sha>`, `latest` и `template-*` не трогаются. Input объявлен в workflow — без него GitHub отвечает 422 `Unexpected inputs provided: ["image_tag"]`. Ветка `layout-draft` получает новый workflow, только когда appspro подтягивает в неё `main`.
